对话上方的目标状态框 · 改版方案

共同前提：默认态尽量矮（目标在跑 2 小时也不该妨碍读对话），详情放在自带滚动的地方 （长内容既不裁切、也不把对话挤没），状态色从整块渐变底收回到 3px 竖条与状态点。 每个页面里的对话区都可以真实滚动，往下滚可以看到目标状态是否还在原位。

为什么现在会「下滑看不了」：这块是 flex: none 排在对话滚动区之外、又没有高度上限； 一旦验收标准多条 + 执行记录展开，它比对话区还高，对话区被压到接近 0； 而它超出卡片的部分被外层 overflow: hidden 裁掉，自身既不滚动也不随页面滚—— 所以往下滚也看不到被裁掉的轮次记录。五个方案都从「详情移出主流程 + 自带滚动」入手解决。
现状（对照）

无高度上限，执行记录一展开就把对话区挤没，溢出部分被裁且滚不动。

A 吸顶单行条 + 右侧抽屉

38px 一行放全部关键指标，详情与执行记录进自带滚动的抽屉。

推荐
B 极简细条 + 悬停浮卡

26px 细线 + 悬停浮卡，操作收进 ⋯ 菜单。

C 工具栏徽标 + 浮层

对话区上方零占用，目标压成工具栏徽标，点开浮层看全部。

D 吸顶台头 + 分段预算

控制台台账风格：状态竖条 + 预算格 + 原因行，详情限高内滚。

E 合成胶囊 + 居中模态

保留圆角卡，压成一行；详情进居中模态（轮次表格）。

我的建议

A 优先：默认一行 38px 把「状态 / 目标 / 轮次 / 耗时 / Token / 中枢」全放在视野里，扫一眼就够； 详情与执行记录进右侧抽屉并自带滚动，彻底解决裁切。
D 次选：如果你更想要与 POC 库台账一致的“控制台”味道（无圆角、预算格、原因单独一行），选 D； 它把执行记录留在原地、只是给执行记录加了高度上限与内部滚动，改动比 A 更靠近现状。
C 适合长目标党：只想让对话区完全干净、把目标当作工具栏的一个状态灯，选 C。
B / E 是省空间与最小改动的两个极端：B 让关键信息依赖悬停，E 用模态查看详情（都会多一层交互）。
