会话分组 + Agent 自主起名 — UI 稿

已定：① set_session_title 工具随时改，人工重命名保留（后写覆盖）；② 提示词引导主动起名；③ 旧工程会话自动对账归组；④ 工程组内按工程分组 + 时间倒序。待选：侧栏形态——方案 1（折叠分组）vs 方案 2（平铺 + 徽章 + 筛选），两稿如下。

方案 1 — 折叠分组：对话 / 工程 两段，工程内按工程名再分节

「对话」段就是现状（状态点 + 悬停改名 + 全部/未完成）；「工程」段独立折叠，内部每个工程一个小节，任务行带状态徽章，运行中实时可点开看流式。

优点：结构最清晰，批量打几十个目标时工程会话不淹没普通对话；工程小节自带状态汇总。

代价：侧栏多一层缩进；「全部/未完成」筛选只作用于对话段，两段各自计数。

交互：段头 / 工程头点击折叠（记 localStorage）；行悬停仍是改名/删除。

方案 2 — 平铺 + 来源徽章 + 筛选器（全部 / 未完成 / 对话 / 工程）

不分组，列表保持一层；工程会话行首带状态徽章、行尾带工程名徽章；筛选器在原「全部 / 未完成」旁加两个维度，可组合（如「工程 + 未完成」）。

优点：单层列表改动最小，时间线一以贯之；筛选维度更灵活（工程×未完成组合）。

代价：大批量时工程会话仍会占满列表，靠筛选救；工程归属靠行尾小徽章，扫视略弱。

交互：「对话 / 工程」与「未完成」是两个独立维度，点选组合；再点取消。

Agent 自主起名（两案通用，行为演示）

set_session_title 工具挂到主 Agent 与工程 worker；提示词引导「任务明确后尽早起一个可检索的描述性标题，范围变化时更新」。人工重命名保留，后写覆盖（人工改完 Agent 再改也会覆盖——按你选的「随时改」）。

参数：{ "title": "10.0.0.5 SQL 注入验证（/api/query 布尔盲注）" }
