工程会话行拥挤修复 — 四种方案

现状问题：任务徽章 + 工程徽章（最长 88px）+ 「无状态」chip + 悬停按钮全挤在 210px 单行里，标题被压到 0 宽——你截图里只剩三个标签。四个方案都保证标题可见，区别在密度和交互。

完成第一批资产无状态

标题（如「第一批资产 · 10.0.0.5 Web 深度测试」）被完全挤出可视区。三个 flex:none 元素 ≈ 200px > 可用 ~178px。

方案 1 — 两行布局：标题独占一行，徽章沉到第二行

标题完整可见（可截断省略），徽章一行放得下；行高约 46px。无状态 chip 仍在，但不再挤标题。

信息最全，列表变高；悬停改名/删除按钮出现在第二行右侧。

方案 2 — 单行瘦身：「无状态」不占位 + 徽章收窄 + 悬停显按钮

19 个会话＋
运行第一批资产 · 10.0.0.5 Web 深…第一批资产无状态✎ 🗑
完成第一批资产 · 10.0.0.1 端口枚…第一批资产待跟进✎ 🗑

保持单行 30px：未设置状态时不渲染「无状态」（悬停该行才出现，点了就能设）；已设置状态（如 待跟进）照常常驻；工程徽章压到 ~56px；悬停按钮只在悬停时出现。

省出 ~110px，标题能显示 ~12 个字（省略号截断）；行高不变、列表最紧凑。

方案 3 — 单行 + 工程徽章缩为首字块（如「第」/「第资」）

运行10.0.0.5 Web 深度测试（内网横…）第✎ 🗑
完成10.0.0.1 端口枚举与指纹第待跟进

标题空间最大（工程徽章只剩一个首字色块，悬停显示全名），单行 30px。

代价：多个工程并行时首字可能重复（「第」「第」），辨识度下降，要悬停确认。

方案 4 — 按工程折叠子分组（回到分组思路，行内零徽章）

标题最长可用空间：工程名升到组头（带运行数汇总），行内只剩状态徽章；多工程折叠后列表最短。

代价：多一层缩进与点击（展开/收起）；实现最重（此前方案 1 的折叠分组回归）。
