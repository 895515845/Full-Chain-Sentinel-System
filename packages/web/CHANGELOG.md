# Changelog

## [Unreleased]

### Breaking Changes

- The console has no default directory any more: without a project there is no container, so the chat is replaced by a full-screen project-required screen with inline project creation and the project list
- Removed the host-session fallback and the `ZG_ALLOW_HOST_SESSIONS` escape hatch, the "back to default directory" picker entry, and `switch_project: null`. Bash, the file tools, and the file panel all require the project container

### Added

- Initial release of the ZGAgent web console: HTTP + WebSocket server embedding the coding-agent SDK, a Chinese React control console (streaming chat, tool cards, session list, mode switch), the bash approval gate with command editing for review mode, and OpenAI-compatible endpoint configuration persisted to `~/.zgagent/agent/models.json`
- Approval queue: every pending command is listed with per-item edit/approve/reject plus approve-all and reject-all
- Session-scoped command-prefix allowlist: approve with "always allow this prefix" or manage prefixes in the chat toolbar; compound commands (&&, ;, |, substitution) never match the allowlist
- Endpoint test connection with actionable Chinese diagnostics (timeout, 401/403, 404 path hint, unknown model); an empty API key no longer invalidates models.json
- Tool output upgrades: copy command, copy output, fullscreen viewer with line filtering
- Session branching UI: a branch tree modal opened from the chat toolbar, plus inline "fork from here" on user messages
- Usage panel (input/output/cache tokens and cost) refreshed after each run
- `get_state` protocol message for pulling a fresh snapshot on demand
- Added the `spawn_agent` tool: the main agent can delegate self-contained tasks (e.g. per-host recon) to isolated in-memory sub-agent sessions with a turn budget; both modes can run commands through the operator approval gate (approval requests are labeled with their source), "explore" excludes the edit/write tools, and sub-agents cannot spawn further sub-agents
- Added project management: named working directories persisted in `~/.zgagent/agent/projects.json`, selected from a picker at the top of the sidebar; sessions, context files, and the bash cwd follow the project automatically
- Switching projects rebuilds the agent session and is locked while a run is active; the server restores the last active project on startup
- Deleting a project requires typing its name, unregisters it, and removes its session directory; the model endpoint stays global
- Manual context compaction: a "压缩上下文" button and a typed `/compact` both compact the viewed session, with pi's English refusal messages ("session too small", "already compacted") reported in Chinese
- Thinking-level control: the chat toolbar lists the levels the active model accepts and switches between them for the current session only
- Image input: paste a screenshot or pick image files, sent as base64 attachments and rendered in the transcript. The endpoint config now declares `input: ["text", "image"]`; without it pi silently dropped every attachment because the provider-model default is text only
- Built-in codemode and tool_search extensions, plus the MCP extension reading `mcp.json` from the agent directory and the project. Sessions now call `bindExtensions()`, which emits `session_start` and lets extensions contribute skills, prompt templates, and MCP servers
- Container file browser and sub-agent monitor (originally a right-hand drawer with two tabs)
- File panel for the container work directory `/work`: browse with breadcrumbs, preview text and images, edit text inline, upload, download, rename, delete, and create directories. Every operation runs through `docker exec` in the project container, so the panel sees exactly what the agent's bash tool sees and keeps container root on bind mounts that are not user-mapped
- Paths are normalized against `/work` and rejected when they escape it; they reach the container as positional parameters, never interpolated into a script. Deletes and renames refuse the work root itself
- Sub-agent panel: every run of the current session with its status, task, turn count, and duration; expanding a run shows the recorded process (assistant text, thinking, tool calls with output) plus its result
- Sub-agent runs and their process steps are stored permanently in SQLite (`<agentDir>/subagents.db`, `node:sqlite`), so a finished run stays reviewable after its in-memory session was disposed and across restarts; runs left `running` by a previous process are closed as interrupted
- Sub-agent controls: abort one run, or steer it with an appended instruction (`streamingBehavior: "steer"`)
- Added an end-to-end smoke suite that drives the full stack against a scripted local OpenAI-compatible endpoint: review-mode gating with an edited command, final-answer streaming, auto-mode passthrough, the container file panel, and sub-agent history. It installs a fake `docker` on PATH so the real container scripts run without Docker
- DingTalk notifications: a finished run posts a markdown message to a group robot with the status (完成/失败/已中止), project, session title, duration, token usage and cost, the closing reply (truncated to 500 characters), and the error when it failed. The settings page configures the webhook, an optional signing secret ("加签"), and an optional custom keyword for keyword-secured robots; a "发送测试消息" button verifies the robot without waiting for a task
- The composer's 通知 pill decides per message whether the run reports to DingTalk. It follows the global switch by default and can force a notification while the switch is off
- Page-based console shell: a grouped side menu (工作台 / 系统) navigates between the 对话, 项目, 设置 and 关于 pages
- 项目 page: the project table lists every project with its container and session count, creates new ones, switches, and deletes with a typed-name confirmation
- 关于 page: read-only summary of the live runtime (connection, endpoint, model, mode, thinking level, active project, working directory, token usage and cost)
- 文件 and 子代理 open as overlays from the chat page toolbar, where they belong to the session being worked on, instead of taking a sidebar entry each. The 子代理 button carries the number of live runs
- Agent tool permissions under 设置 > 权限: per-agent switches for read, bash, edit, write, codemode, tool_search, MCP and spawn_agent, persisted globally in `~/.zgagent/agent/permissions.json`, with one-click 标准 / 只读侦察 / 全部禁用 presets. A sub-agent can never hold a tool the main agent does not have, and never gets spawn_agent, so disabling bash for the main agent cannot be bypassed by delegating
- Permission enforcement uses the SDK's `excludeTools` denylist, so a disabled tool is dropped at registration: it is not declared to the model, `tool_search` cannot activate it, a transcript cannot restore it, and a codemode script cannot call it. Saving rebuilds every live session (history preserved) and is refused while a run is active; the page also lists the tools the live session actually mounted
- A finished run folds into one 过程 row: its thinking, tool calls and intermediate remarks collapse into a single line carrying a digest (tool calls, thinking rounds, elapsed time), leaving the prompt and the final answer in the transcript. Expanding the row puts the whole process back in order. A failure, an abort or a run still in flight never folds, so the error stays visible
- Tool calls read as a timeline inside their run: a rail down the text column with a node per call (blue while running, green when done, red on failure), the tool name, one line of the command or of the latest output, and the outcome on the right. Expanding one turns it into the dark terminal block with the command, the full output, copy and fullscreen
- Single-file binary: `scripts/build-web-binaries.sh` compiles the whole console with `bun build --compile` into one executable (darwin-arm64, linux-x64) that carries the server, the browser UI, the toolbox Dockerfile and the coding-agent package files. It starts with `--port`, `--host`, `--cwd`, `--version`, `--help`, and `--check`, which runs the environment check and exits non-zero when it fails
- Embedded web assets: `webui/dist` is gzipped and base64-encoded into `src/embedded-assets.generated.ts` by `scripts/generate-embedded-assets.mjs` (run automatically by `npm run build`). The server serves the frontend from disk when it exists and from the embedded copy otherwise, so a binary needs no files beside it
- 环境 page under 设置: the console checks the Docker CLI, the daemon, the `zgagent:latest` image, the image/host architecture match, a throwaway container start, the project containers, the project and agent directories, free disk space, the model endpoint, and the build network. Each row carries a status (通过/警告/失败/跳过), the observed value, and a fix hint; 复制诊断 copies the report as text
- 构建镜像 on the 环境 page: builds `zgagent:latest` from the checkout's `docker/` directory, or from an embedded copy of the Dockerfile written to a temp directory when running as a binary, streaming the build output into the page with 中止构建 to cancel
- Docker gate: while a blocking check fails, the console refuses `prompt`, `compact`, and `steer_subagent` with the failing check as the reason, shows a banner above every page, and locks the composer (disabled input, 已锁定 status) instead of letting a run fail in the container
- Runtime SQLite shim (`src/sqlite.ts`): the sub-agent store loads `bun:sqlite` under Bun and `node:sqlite` under Node, so the same code runs from a Node checkout and from a compiled binary, which has no `node:sqlite`
- `setEmbeddedPhotonWasmPath()` in the coding-agent, used by the binary entry so image attachments keep resizing without a `node_modules` next to the executable

- 环境页新增「工作目录挂载」检查：逐个容器读取挂载表，发现容器只在 `/work` 挂了项目目录、没有按宿主路径挂载时给出警告（不阻断），并提示重建前先用 `docker cp` 把容器内该路径下的文件捞出来
- Build sources on the environment page (设置 → 环境 → 构建源): the base image can point at a Chinese accelerator or an internal registry, and apt / pip / npm / go can each use a mirror, with a one-click 中国镜像源 preset. The values are passed to `docker build` as `--build-arg` and baked into the image, so pip/npm/go also apply to installs made inside a running container. Stored in `~/.zgagent/agent/sources.json`; a bare registry (`docker.m.daocloud.io`) expands to the official repository on it, and a mirror without a scheme gets `http://` for apt and `https://` for the rest
- The bundled Dockerfile accepts `BASE_IMAGE`, `APT_MIRROR`, `PIP_INDEX`, `NPM_REGISTRY` and `GO_PROXY` build arguments. The apt rewrite handles both deb822 (`/etc/apt/sources.list.d/kali.sources`) and the older `sources.list`, and ca-certificates is installed from the original source first so https mirrors work (that step is allowed to fail, so an unreachable original source only affects https mirrors)
- Environment check item "构建源": shows the base image and the four mirrors the next build will actually use
### Changed

- `spawn_agent` no longer takes a `mode`. A sub-agent now gets the same tools as the session that spawned it, including the ones the loaded extensions contribute (`codemode`, `tool_search`, MCP servers), plus the approval-gated bash. `spawn_agent` is the one tool withheld, which is what keeps delegation from recursing. The sub-agent panel no longer shows a mode, and `subagents.db` drops its `mode` column (existing databases are migrated in place on open)
- The settings page is now split into 模型 and 通知 pages under the sider's 设置 entry, so the endpoint form and the notification form each get a full page; the failure hints that pointed at "模型设置" now say "设置"
- Deleting the active project now detaches the runtime from it, so the console returns to the project-required screen instead of pointing at a deleted container
- The console layout follows the reference admin console: a 210px dark sider (`#001529`) with a 54px brand row, 40px menu rows and 34px indented submenu rows, over a `#fafafa` content area with 16px-padded white cards at a 6px radius
- The right-hand drawer is gone: 文件 and 子代理 open as wide overlays (min(1080px, 100vw - 64px) by min(84vh, 780px)) over the chat page, so the file browser and the sub-agent monitor are no longer capped to a 380px column
- The conversation is rendered as a console log instead of a chat: the OPERATOR/AGENT role tags and message bubbles were removed, operator input is echoed as a command line, and tool calls are dark terminal blocks. Execution policy (mode, thinking level, branch, compaction, command-prefix allowlist) moved from the composer to the chat page toolbar, leaving the composer with just the message, its attachments and the notification switch
- The sidebar became a grouped sider whose 对话 entry carries the session list as a submenu (running indicator, inline rename, delete), and whose 设置 entry expands into 模型 and 通知. Clicking either row expands it, or collapses it when it is already the page you are on; the chevron is an indicator rather than a second click target. The session list starts open, the settings submenu starts folded. Command-prefix management moved to the chat toolbar
- Replaced the emoji and text glyphs the UI used as icons (⑂, ⤓, 🗀, ⛬, 🖼, ✏, ×, ▸/▾, ⌃/⌄, ↑) with `lucide-react`. All icons go through `webui/src/components/icons.tsx`, which pins size and stroke weight, so the toolbar buttons, menu rows, tool cards, branch tree, project picker and file panel now share one icon set
- The no-project screen now replaces the chat page only. 设置 and 项目 stay reachable without a project, so a first run can reach 设置 → 环境 and build the image instead of being stuck behind the gate
- `npm run build` in `packages/web` now builds the frontend first, then regenerates the embedded assets, then compiles TypeScript, so the embedded copy can never lag behind the served one. `build:assets` and `build:binary` run the steps separately

- 项目容器现在把宿主项目目录挂载两次：`<宿主目录>:/work`，以及 `<宿主目录>:<宿主目录>`。系统提示词把宿主工作目录（会话 cwd）交给模型，而 bash 在容器内执行，于是模型用绝对路径写文件时会落到容器自己的可写层——文件到不了宿主机，read/write/edit 与文件面板都看不到，容器一重建就丢。同路径挂载后两种写法指向同一个目录（同一 inode），提示词与文件工具都不用改
### Fixed

- The transcript no longer loses or reorders a run's output: messages committed by the event stream render in arrival order and the settled snapshot absorbs them, instead of the assistant text being dropped at every message end while every tool card was pushed to the bottom of the page until a manual refresh
- Switching sessions or projects clears the event-built transcript, so the previous session's live tail no longer sits under the new transcript until a refresh
- DingTalk notifications follow the run instead of the view: a task that settles while another session is on screen is reported, where the previous gate on the viewed session silently dropped it
- The connection indicator reports the real socket state (已断开 when it closes), the console re-reads its state on every reconnect, and a dropped connection shows a banner instead of leaving stale content on screen
- The startup banner prints an openable address when the server binds a wildcard host: `http://0.0.0.0:<port>` is not a browser address and Chrome answers ERR_ADDRESS_INVALID for it
- The console reported the session as idle while a run was in flight: `streaming` came only from a snapshot, and the server broadcasts those at run boundaries, so the abort button never appeared, the status line read 空闲, and the transcript could not tell a running task from a finished one. The flag now tracks the run's own events, and every snapshot re-states it
- Sub-agents could not execute commands at all: the `explore` mode's tool set was `read`/`grep`/`find`/`ls`, so a delegated task that had to run something (the common case, e.g. recon) came back with "no bash tool mounted"
- Fixed sessions running with only `bash` and `spawn_agent`: the runtime's `baseToolsOverride` replaces the whole base tool set, so `read`, `edit`, and `write` must be named explicitly alongside the gated bash. The system prompt's tool section now lists all four with their snippets and guidelines instead of the custom tools alone.
- Fixed the context-overflow hint pointing at `/compact`, which pi only handles in interactive mode; the console now honors that command itself
- Concurrent bash tool calls previously surfaced only one approval at a time
- Saving a config with an empty API Key wrote `apiKey: ""`, which fails models.json validation and dropped every provider; unauthenticated endpoints now get a placeholder bearer Pi accepts (endpoints ignore it)

- `buildImage` used a context directory two levels above the repository (`<repo>/packages/docker`), which does not exist, so the first image build would have failed. It now resolves the repository root correctly and falls back to a temp directory holding the embedded Dockerfile
- A compiled binary lost the fork identity: with no `package.json` beside the executable the coding-agent fell back to pi's defaults, reading `PI_CODING_AGENT_DIR` and storing state in `~/.pi/agent`. The binary now unpacks the embedded package files into a temp directory and points `PI_PACKAGE_DIR` at it before the coding-agent loads, so `ZGAGENT_CODING_AGENT_DIR` and `~/.zgagent/agent` apply as they do in a checkout
