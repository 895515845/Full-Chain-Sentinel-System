# ZGAgent Web

ZGAgent 的 Web 控制台：内嵌 pi coding-agent SDK 的 HTTP + WebSocket 服务，以及浏览器端中文控制台界面。

## 功能

- **控制台布局**：左侧分组侧边菜单（工作台 / 系统）。对话、项目、设置、关于是页面，导航只有侧边栏一个入口；「文件」与「子代理」不再是独立页面，而是从对话页工具栏打开的弹窗，因为它们都是针对当前会话/项目的操作，放在侧边栏会割裂上下文。项目选择器固定在侧边栏顶部，因为所有页面都作用于当前项目的容器
- 流式对话（文本 + 思考过程）与工具执行卡片实时展示（含长命令执行中的滚动输出）
- 双执行模式：
  - **审批模式（默认）**：bash 命令执行前弹出审批，可编辑命令后放行或拒绝
  - **自动执行**：命令直接运行，不做拦截
- **子代理（spawn_agent）**：主代理可将独立子任务（如单主机侦察）委派给隔离子会话并行执行。子代理的工具集与本会话一致（含扩展提供的 codemode / tool_search / MCP 工具），再按「设置 → 权限」中给子代理勾选的开关收窄（永远是主 Agent 的子集）；bash 同样经过审批门（弹窗标注来源）；唯一永远不给的是 spawn_agent，因此不能再派生子代理
- 审批队列：并发工具调用逐条列出，可单条批准（可编辑）、全部批准、全部拒绝；支持「本会话自动放行此前缀」与命令前缀白名单（复合命令永不白名单放行）
- **设置页**（侧栏「系统 → 设置」，点击「设置」行展开/收起，展开时进入「模型」）：分「模型」「通知」「权限」「环境」四个页面。模型分区配置 OpenAI 兼容端点，保存前一键验证，失败给出具体原因（超时 / 401 / 404 路径 / 模型不存在）与建议；空 API Key 的本地端点可直接使用
- **Agent 权限**（设置页「权限」）：主 Agent 与子 Agent 各一组开关（read / bash / edit / write / codemode / tool_search / MCP / spawn_agent），全局保存在 `~/.zgagent/agent/permissions.json`，另有「标准 / 只读侦察 / 全部禁用」三个预设。子代理的权限永远是主 Agent 的子集，且永远拿不到 spawn_agent——否则主 Agent 关掉 bash 后只要派一个子代理就绕过了自己的限制。保存后立即重建所有活动会话（历史保留），有运行中的会话会拒绝保存并要求先中止。禁用是通过 SDK 的 `excludeTools` 在注册阶段剔除工具实现的，因此模型看不到、tool_search 搜不到、历史记录恢复不了、codemode 也调不到；页面同时列出当前会话实际挂载的工具，便于核对
- **环境页**（设置页「环境」）：进入页面或点「复检」时检查 Docker 命令行、守护进程、`zgagent:latest` 镜像、镜像与宿主架构是否一致、一次性容器能否启动、项目容器是否都在运行、项目目录与配置目录是否可写、剩余磁盘空间、模型端点是否配置、构建镜像需要的网络。每项给出状态（通过 / 警告 / 失败 / 跳过）、实测值和修复建议，「复制诊断」把整份报告复制成文本
- **构建源**（设置页「环境」→ 构建源）：基础镜像可换成国内加速站（如 `docker.m.daocloud.io`，只填 registry 会自动补 `kalilinux/kali-rolling:latest`）或内网 registry，apt / pip / npm / go 可分别指向镜像源，另有「中国镜像源」一键预设（清华 apt、清华 pip、npmmirror、goproxy.cn）。这些值作为 `docker build --build-arg` 烘焙进镜像，所以保存后要重建镜像；pip / npm / go 三项同时写进镜像里的 `/etc/pip.conf`、`/root/.npmrc`、`/root/.config/go/env`，容器内运行时执行 `pip install` 等也走镜像源。留空即官方源，保存在 `~/.zgagent/agent/sources.json`，环境页的「构建源」检查项会列出下次构建实际使用的值
- **构建镜像**：镜像不存在时在环境页直接点「构建镜像」构建 `zgagent:latest`（二次确认，构建输出实时滚动，可「中止构建」）。仓库里运行时用 `docker/` 目录作构建上下文；单文件二进制运行时把内嵌的 Dockerfile 写到临时目录再构建，因此不需要带任何文件
- **Docker 门禁**：只要有阻断项没通过，控制台就拒绝 `prompt`、`compact` 和子代理 steer（服务端返回失败原因），所有页面顶部显示红色横幅，输入框锁定为「已锁定」并显示原因——与其让命令在容器里失败，不如先让人把环境修好。未选项目时引导页只替换对话页，设置页与项目页仍然可达，否则首次使用就没法进环境页构建镜像
- **钉钉通知**（设置页「通知」）：一次运行结束（完成 / 失败 / 已中止）后向钉钉群自定义机器人推送 markdown 消息，含状态、项目、会话、耗时、token 用量与花费、最后回复（截断 500 字）与失败原因。支持「加签」（secret 留空则不加签）与「自定义关键词」；「发送测试消息」可先验证机器人。输入框旁的「通知」开关按条决定本次运行是否推送，默认跟随全局开关，全局关闭时也可单条强制发送；发送失败重试 2 次，最近一次发送结果显示在设置页
- 长输出查看：复制命令 / 复制输出 / 全屏查看 + 行过滤搜索
- 会话分支：对话页工具栏「分支」打开分支树弹窗，任意历史用户消息处一键分叉
- 用量统计：输入 / 输出 / 缓存 token 与费用
- **项目管理**：命名的独立工作目录（侧栏顶部选择器切换，或「项目」页管理），会话/上下文文件/bash 目录按项目自动隔离；删除项目需输入项目名确认并连带清理其会话；重启自动恢复上次项目。**没有默认目录**：未选择项目时对话区显示创建项目的引导页，不能开始对话
- **文件弹窗**（对话页工具栏「文件」）：浏览容器工作目录 `/work`，支持预览文本与图片、在线编辑并保存、上传、下载、重命名、删除、新建目录。所有操作都通过项目容器内的 `docker exec` 执行，因此看到的就是 bash 工具看到的目录，并保留容器 root 权限（bind mount 未做用户映射时仍可读写 root 创建的文件）
- **子代理弹窗**（对话页工具栏「子代理」，按钮上显示运行中数量）：列出当前会话的每个子代理运行（状态 / 任务 / 轮数 / 耗时），展开可见完整过程（文本、思考、工具卡片与输出）与最终结果；可单独中止某个子代理，或给它追加指令（steer）。运行记录永久保存在 `<配置目录>/subagents.db`（SQLite），会话销毁或控制台重启后仍可回看
- **手动压缩上下文**：把当前会话压缩成摘要后继续（对话页工具栏「压缩上下文」按钮，或直接输入 `/compact`）；上下文超限报错时提示该操作
- **思考等级**：按模型能力列出可用等级（关闭 / 最低 / 低 / 中 / 高 / 极高 / 最大），在对话页工具栏即时切换，只对当前会话生效
- **图片输入**：粘贴截图或选择图片文件随消息发送，会话记录中保留缩略图。注意 pi 只会把图片发给声明了 image 能力的模型，本控制台写入的端点配置默认声明 `input: ["text","image"]`；纯文本端点请在 `models.json` 中改回 `["text"]`
- **内置扩展**：codemode（沙箱内脚本批量调工具）与 tool_search 默认启用；MCP 服务器从 `~/.zgagent/agent/mcp.json` 与项目目录的 `mcp.json` 读取，会话启动时连接
- 会话管理：会话挂在侧边栏「对话」下（悬停显示重命名 / 删除）、切换、新建（JSONL 会话文件即审计日志）
- 会话记录按控制台日志呈现：操作者输入是一行命令回显，代理输出是正文段落。一次运行的过程（思考、工具调用、中间说明）挂在正文左边缘的一条竖轨上，每次调用是轨上一个圆点：运行中蓝色、完成绿色、失败红色，行内显示工具名、命令或最新一行输出、以及结果与耗时；点开某一行才变成深色终端块（命令、完整输出、复制、全屏）。**运行一结束，整段过程自动折成一行「过程 · N 次工具调用 · N 段思考 · 耗时」，正文只留你的指令和最后的总结**，点开可完整回看；失败、中止和正在跑的运行不折叠，错误一定看得见。输出顺序由事件流决定：运行期间消息按到达顺序渲染，运行结束的 snapshot 再统一接管，不会出现文字消失或工具卡片堆到最后（刷新才恢复）
- **单文件二进制**：`scripts/build-web-binaries.sh` 用 `bun build --compile` 把服务端、前端资源、Dockerfile 和 coding-agent 的包信息打进一个可执行文件（darwin-arm64 / linux-x64），目标机器上不需要 Node、npm 或 node_modules，只需要一个 Docker 守护进程
- 模型端点配置：OpenAI 兼容端点（vLLM / one-api / new-api 等），写入 `~/.zgagent/agent/models.json`

## 架构

```
浏览器（React，中文界面）
   │  WebSocket /ws（JSON 协议，见 src/protocol.ts）+ 静态资源 HTTP
server.ts（node:http + ws）
   │  直接调用 SDK
zg-session.ts —— createAgentSession() + baseToolsOverride(bash 包装审批门)
   │                    │
   │                    └── files.ts / subagent-store.ts（docker exec 文件操作、子代理记录）
   │
pi coding-agent（AgentSession / SessionManager / 工具 / 压缩 / 会话树）
```

bash 工具通过 `BashOperations.exec` 包装实现审批拦截：审批模式下命令先广播到所有已连接的控制台，等待操作员决定（批准 / 编辑后批准 / 拒绝）；中止运行会取消未决审批。

文件面板与子代理面板不经过审批门，但都限制在项目容器内：文件操作把路径归一化到 `/work` 之下并以位置参数传给容器脚本（不做字符串拼接），子代理只能由主代理派生且同样使用被包装的 bash。

## 使用

在仓库根目录：

```bash
npm install --ignore-scripts
npm run build          # 构建所有包（包括本包）
npm --prefix packages/web run start
```

打开 http://127.0.0.1:7777 。

### 单文件二进制

```bash
./scripts/build-web-binaries.sh                      # darwin-arm64 + linux-x64
./scripts/build-web-binaries.sh --platform linux-x64 # 只构建一个平台
./scripts/build-web-binaries.sh --skip-build         # 复用已有 dist
```

产物在 `packages/web/binaries/`：`zgagent-web-<平台>.tar.gz`，解压后是一个 `zgagent-web` 可执行文件，拷到目标机器直接运行：

```bash
./zgagent-web --check          # 只跑 Docker 环境检查，未通过时退出码 1
./zgagent-web --port 7777      # 启动控制台
```

二进制里带着前端资源和 Dockerfile，所以旁边不需要任何文件；运行时把 coding-agent 的 `package.json`、README、CHANGELOG 和 docs 解包到系统临时目录（`$TMPDIR/zgagent-web-package`）并指向它，否则 pi 会退回自己的默认值，把状态写进 `~/.pi/agent`。它仍然需要目标机器上有 Docker 守护进程和 `zgagent:latest` 镜像（环境页可以直接构建）；linux-x64 产物链接 glibc，Alpine 等 musl 发行版需要额外兼容层。

首次使用先在侧栏「设置 → 模型」配置端点（或在 `~/.zgagent/agent/models.json` 手动配置），在「设置 → 环境」确认 Docker 与 `zgagent:latest` 镜像可用（缺失时可直接构建），然后新建一个项目：控制台没有默认目录，未选择项目时只能看到创建项目的引导页。

```json
{
	"providers": {
		"zg-endpoint": {
			"baseUrl": "http://127.0.0.1:8000/v1",
			"api": "openai-completions",
			"apiKey": "sk-…",
			"models": [{ "id": "deepseek-v3.1" }]
		}
	}
}
```

环境变量 / 命令行参数：

| 参数 | 说明 | 默认 |
|---|---|---|
| `ZG_PORT` / `--port` | 监听端口 | 7777 |
| `ZG_HOST` / `--host` | 监听地址 | 127.0.0.1 |
| `ZG_CWD` / `--cwd` | 未进入项目前的占位目录（不用于执行命令） | 进程当前目录 |
| `ZGAGENT_CODING_AGENT_DIR` | 配置目录 | ~/.zgagent/agent |
| `ZG_PROJECTS_DIR` | 项目工作目录的父目录 | ~/.zgagent/projects |
| `--check` | 只运行环境检查并打印结果，未通过时退出码为 1 | — |

## 安全提示

- 审批模式只拦截 bash 工具；read/edit/write 不拦截。
- **文件面板不经过审批门**：它以容器 root 身份上传、覆盖、重命名和递归删除 `/work` 内的文件，`/work` 之外与工作目录根节点本身会被拒绝。路径按文本归一化（`..` 会被折叠后校验），但**不解析符号链接**：容器内指向 `/work` 之外的软链接仍会被跟随。能改容器内文件的操作员本来就持有容器 root，因此这里只做边界保护，不做权限隔离。
- **MCP 工具与 codemode 不经过审批门**：它们不是 bash，`code` 工具在沙箱内调用工具时仍走被包装的 bash，但 MCP 服务器暴露的工具会直接执行。启用 MCP 前请确认服务器来源可信。
- **路径只有两个名字，指的是同一份数据**：项目目录在容器里同时挂在 `/work` 和它的宿主绝对路径上（同一 inode），bash 用哪种写法都写进共享卷；容器自己的 `/tmp` 与宿主机 `/tmp` 无关，read/write/edit 看不到，只能作为容器内的临时中转。系统提示词给模型的是宿主路径，所以同路径挂载是必要的——否则用宿主路径写文件会落进容器可写层，宿主机和文件面板都看不到，容器一重建就丢。老容器（在本次改动前创建的）没有这条挂载，环境页会给出「工作目录挂载」警告，重建前先用 `docker cp` 把容器内该路径下的文件捞出来
- 控制台会加载项目工作目录下的 `settings.json`、`.pi/extensions`、`AGENTS.md` 与 `mcp.json`。与 CLI 不同，这里没有项目信任确认步骤：不要把这些文件来自不可信来源的工作目录设为项目。
- 自动执行模式下模型可运行任意命令。pi 无内建沙箱，请仅在授权目标与隔离环境中开启自动执行，必要时配合容器化运行。
